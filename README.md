# 电商搜索页商品采集

淘宝、京东、闲鱼的搜索列表采集工具。输入关键词和目标数量，**首次搜索后一直保留结果页，通过页面上的「下一页」控件继续翻页**，按商品 ID 去重，达到目标立即停止，不打开商品详情页。

每页读取浏览器自身返回的搜索响应或当前商品卡片。第二页起不重新提交关键词、不重复打开搜索地址，也不拼接下一页 URL。没有下一页、分页控件不可识别，或点击后商品没有更新时停止并说明原因，不会改回重新搜索。

列表信息和能下载的主图保存为带图 Excel，同时输出 JSON 与图片目录。价格、销量、评论或想要人数、店铺/卖家、地区等仅保存搜索结果中实际提供的字段；未提供的留空，不通过详情页补齐。图片下载失败仍保留商品记录、图片链接与失败状态。

## 安装与运行

需要 Python 3.10+ 和 Google Chrome。当前浏览器翻页流程不需要 Node.js 或单独运行接口签名器；旧版接口代码只作兼容参考。

```powershell
python -m pip install -r requirements.txt
python app/启动.py
```

也可双击 `2-开始采集.bat`。选择平台、输入关键词和商品数量即可。首次采集需要在弹出的浏览器内手动登录。

淘宝、京东、闲鱼首次没有账号登录态，或搜索时被服务器判定会话已过期，都会打开对应页面等待登录。请在浏览器中手动登录，再回到终端按 Enter；未检测到账号登录时继续等待，输入 q 可取消。正常采集只搜索一次；会话过期重新登录后，需要重新建立一次搜索结果，再通过「下一页」逐页回到中断位置，已经导出的商品不会重复计数。每次采集最多进行一次过期会话恢复，仍失败时保存此前已采到的数据。三个平台的独立入口都支持 `--relogin` 主动重新登录，无需手动删除登录目录，例如 `python vendor/taobao/xuanzeshuliang.py --relogin --limit 40`。

独立运行示例：

```powershell
python vendor/taobao/xuanzeshuliang.py --keyword 纸巾 --limit 50
python vendor/jingdong/jd_sku.py --keyword 纸巾 --limit 50
python vendor/xianyu/xianyu.py --keyword 机械键盘 --limit 50
```

`--max-pages 100` 是自动翻页上限，默认 100；`--no-images` 可只保存图片链接。统一菜单不要求输入页数。程序会根据实际去重产量估算还需要多少页，并继续补足；估算不是平台结果总量的保证。

## 输出与停止条件

结果在 `output/`，每次使用独立文件名。JSON 包含目标数量、实际数量、已获取页数、是否达到目标和停止原因。

达到数量、搜索为空、整页没有新增商品、搜索请求失败或达到页数上限时停止。翻页阶段按 Ctrl+C 也会保存此前获得的数据。未达到目标时保存部分结果并返回退出码 2，不宣称完整采集成功。图片下载失败不影响其他商品保存。

只访问搜索列表仍可能遇到登录失效、验证码或平台风控；程序不会自动解决验证码。登录资料保存在本机 `profiles/`，不随源码上传。

启动时优先复用浏览器中的现有状态，并从本机 `profiles/<平台>/login_state.json` 恢复 Chrome 退出后可能丢失的会话 Cookie；不会用旧备份覆盖已有的新 Cookie。自动恢复登录不会清空 Cookie，也不会仅因为页面存在登录 iframe 就要求重登。只有主动使用 `--relogin` 才会清理本工具当前平台的 Cookie。服务器明确使会话过期时，仍需本人手动登录；先前已被清掉且未备份的登录无法凭空恢复。

## 验证

```powershell
python -m unittest discover -s tests -v
```

已验证去重补页、数量截断、结果不足、失败后保留数据和图片嵌入。浏览器回归测试使用隔离的测试页面，验证三个平台翻到第二、第三页时只点击下一页、没有再次导航，及末页、分页按钮缺失、点击后页面未更新的处理。三个独立入口已通过 `--help` 检查；未完成三个平台的实时登录采集验证，网站布局变化仍需实机确认。

2026-11-20 已复用现有闲鱼登录目录做真实页面验证：关键词 `ai`、目标 40 条，第一页 30 条，点击页码右侧的无文字右箭头进入第二页并补足 40 条去重商品。程序只主动打开一次搜索地址，导出带图 Excel；闲鱼箭头按实际 DOM 结构定位，不依赖 class 的构建哈希后缀。淘宝、京东尚未登录实测。

三个运行入口统一进入 `app/search_collect.py` 和 `app/browser_search.py`。旧版接口、详情解析代码保留供兼容参考，当前入口不调用它们进行翻页或详情采集。
